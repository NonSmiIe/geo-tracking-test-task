The implementation now passes real-PostGIS integration checks and the initial load run reconciled every submitted report across all subscribed sessions. Its first sustained acceptance run failed because a 128-worker generator dropped 316 of 1,800,000 scheduled reports and end-to-end p95 was 1,103 ms. The next run must use adequate bounded producer concurrency and pass the full workload gate; this is not a completed performance proof.

Plan: [implementation plan](plan-2026-10-01.md). Requirements: [source evidence](research-2026-10-01.md). Repository: this repository.

## Concrete findings and corrections

- The adversarial reviewer reproduced an unmanaged WebSocket race during the ready handshake. Connection publication now queues ready, starts its writer and registers atomically after accept; opening reservations count toward capacity. Regression tests exercise delayed accept and blocked ready-send overflow.
- A zero-accepted workload could formerly pass delivery reconciliation. Workload admission, exact scheduled population, cadence and latency now have separate acceptance gates.
- Millisecond Date.parse ordering lost microsecond position updates. The replacement UI uses microsecond keys and its browser test sent `.000100Z` then `.000900Z` successfully.
- The maximum-zone-radius candidate query was 2,090.025 ms with one global-radius outlier. The replacement indexed radius-bucket query was 25.123 ms; normal varied-radius cases were 1.638 ms and 13.6 ms respectively. Fixtures contain 10,000 zones and 200 reports; results are query-spike measurements, not end-to-end throughput.
- Actual SDK structured-output tests verify private user context, no automatic mutation, invalid centre/radius rejection and unavailable configuration. No live OpenAI model request ran because no key was supplied.
- The Impeccable UI agent used a source-file browser overlay while the application container was held stable for the initial baseline. Final no-overlay verification must follow a production rebuild. Desktop/mobile source checks and screenshots are in `evidence/ui/`; keyboard focus and selected-view semantics were identified for correction.

## Initial sustained run

Apple M4 Pro, native ARM64 Docker; app limited to 2 CPUs/512 MiB and database to 2 CPUs/1 GiB. PostgreSQL 17.6, PostGIS 3.6.4. Fixture: 10,000 moving devices, 5-second interval, 100 private test zones, two owner sessions and one other-user session.

Scheduled 1,800,000; submitted and accepted 1,799,684; generator dropped 316. Delivery checksums and counts reconciled in all sessions, with no HTTP rejections or transport errors. End-to-end p95 1,103 ms includes waiting in the producer queue; it exceeded the one-second acceptance target. App ingress high-water stayed around 130 because producer concurrency, rather than server admission, bounded offered requests. Final app RSS sampled around 101 MiB and database around 117 MiB. Raw evidence is `evidence/baseline-initial.json`; full final results remain pending.
