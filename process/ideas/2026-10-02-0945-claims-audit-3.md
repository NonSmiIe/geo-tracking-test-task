# Claims audit 3 (raw)

Triage: [ideas](../ideas.md). Numbers were checked against JSON fields (`acked_reports_per_second`, `delivery_latency`, `resources.containers.*.cpu_median_percent`, `pipeline`, `fault_run`) and the statement files.

## FALSE

- **F1:** README:122 "pool 4 per processor"; the code has `pool_size=1`.
- **F2:** design §09 "2 per processor, batch up to 2,000"; it is 1 and 10,000.
- **F3:** design §04 and §03 still describe lanes: "poll ≤ 2,000", a separate watermark read, "the lane then matches".
- **F4:** README:130 and design §03 "alert frame 1,000 items"; frames are bounded by bytes since 1cf61ae.
- **F5:** design §09 "a crash between commit and publish loses those live frames"; they are re-emitted, which contradicts README:65.
- **F6:** design §06 "replayed samples count as stale"; they are re-emitted.
- **F7:** README:59 "cost per row falls as traffic rises"; the batch-window run refutes it.
- **F8:** README:211 exact-timestamps row copied from s1. The JSON has 59,823/s, api 52/55/54/54, db 149, processors 22.
- **F9:** README:212-213: the JSON has 59,917 and 59,893/s; api 51 and 55; db 128; processors 18 and 18.
- **F10:** "alerts within 12 ms of positions"; one-writer is +15/+21 and batch-window +14.
- **F11:** "Kafka CPU doubled"; the median went 67.1 → 87.8 (+31%).
- **F12:** "radii 1e-100 to 1e100 m"; the test's largest is 500 km.
- **F13:** "60 zones"; the test uses 51.
- **F14:** README:145 "sharding by device_id"; the design keys shards by partition.
- **F15:** "two 300k runs measured the harness"; h5 was a service defect.
- **F16:** "the only published port"; three are published.
- **F17:** "every container runs with no-new-privileges"; the `tests` service lacks it.
- **F18:** "the manifest does not repeat allowIdleConsumers"; processor.yaml sets it.
- **F19:** "16 ms / 8 µs per row idle"; the probe shows 11.6 ms and 5.8 µs.
- **F20:** "HOT 98.6%"; the probe shows 98.3%.
- **F21:** "every rung reconciled … never on loss"; tx1, tx1-repro and h5 failed reconciliation (the clamp and h5).
- **F22:** hero 59,935/s from s1 beside 876 ms from another run.
- **F23:** "gateway lines … carry request_id"; evictions are logged from the NATS callback, outside the request context.
- **F24:** "edge stats on :8404"; only `/metrics` is served there, and the port is not published.

## UNSUPPORTED

- **U1:** 876 ms "on the current build"; the run was at c0812d8, before 1cf61ae.
- **U2:** "handover restarts stages past the deadline … passed"; nothing shows that path fired, and s9-one-writer is not cited.
- **U3:** 247 rows and 34 µs come from secured-statements, not exact-timestamps.
- **U4:** "byte cap holds roughly 2 h" is an unlabelled estimate.
- **U5:** "split ingest 1.9×" and "1.7 MB/s" have no evidence file.
- **U6:** "replies subscribed once NATS subscriptions are live"; the gateway never flushes or waits for the server to confirm.
- **U7:** "20,000 lag ≈ 3 s of measured throughput"; that is a share of the offered load, not capacity.
