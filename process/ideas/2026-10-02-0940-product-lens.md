# Product lens (raw)

Triage: [ideas](../ideas.md). Read-only. Every cost below is an estimate, not a measurement.

The keystone is one table, `zone_events`, written inside the batch transaction. Entry and exit, dwell, webhooks and alert history after a reconnect all build on it, and replay becomes exact because a stored log can be re-read.

## Features, ranked by value ÷ cost

1. **Zone entry and exit events with an event log.**
   - *Value:* "arrived at the depot at 14:02, left at 14:40".
   - *State:*
     - `zone_membership(device_id, zone_id, zone_version, entered_us, dwell_alerted)`, primary key `(device_id, zone_id)`;
     - `zone_events(partition, offset, zone_id, user_id, device_id, kind, at_us, dwell_us)`, primary key `(partition, offset, zone_id, kind)`, partitioned by day.
   - *Owner:* the processor only. The membership write runs after the `device_latest` upsert in the same transaction, so the upsert's row lock orders a zombie owner and a new one.
   - The api never writes membership. An edited, paused or deleted zone is noticed when the device next reports: the read joins `geozones`, and a changed version or missing zone is re-checked.
   - *Per batch:* read membership for devices with fresh samples, walk their fresh samples in timestamp order against the `MATCH_SQL` result (never collapsed, so in → out inside one batch gives both events), then write.
   - *Replay:* records at or below `consumer_progress` re-read their events by `(partition, offset)`, because membership has already moved on.
   - *Delivery:* `zone_entered` and `zone_exited` frames on the alerts subject, plus `GET /zone-events?since=`, which removes the "alerts not replayed after a disconnect" limit.
   - *Cost:* about 430 primary-key probes per batch (est. 1–2 ms); writes only on transitions (60–600 events/s for a realistic fleet); rows equal occupancy.
   - *Invariants:* entry-only alerts are rejected in decisions, so `inside_report` stays. This reopens the transactional-outbox rejection for transitions only, which needs a decision entry.
   - *Proof:* tests for in-in-out inside one batch, identical event ids after a crash between commit and publish, a zombie owner, a version bump, pause and delete. A 300k crossing fixture with geographiclib ground truth, reconciled by count and checksum, under policy v5 declared first.
2. **Dwell time and dwell alerts.** `entered_us` from feature 1; the exit carries `dwell_us`; a per-zone `dwell_alert_s` fires once.
3. **Device offline and back-online.**
   - Back online: the gap is already in the upsert's `RETURNING`.
   - Offline: an advisory-locked sweeper seq-scans `device_latest` (est. 30 ms per 300k every 5 s; no index, to keep HOT updates) and produces a marker keyed by `device_id` into `reports`. The owner applies it only if `reported_at` still equals the marker's value, and closes membership.
4. **Polygon zones.** `center` becomes `area geography`, matched by `ST_DWithin(area, point, radius_m)`, with the footprint as an expanded bounding box and at most 500 vertices. The superset test is extended to random polygons, including antimeridian ones.
5. **Webhooks**, from `zone_events` only. A separate dispatcher with a cursor per subscription, HMAC signatures, retry with backoff and a circuit breaker; never an HTTP call in the processor.
6. **Schedules and speed rules.**
   - Schedules are evaluated against the sample's own timestamp, so a replay is deterministic.
   - Speed uses `lag()` over fresh samples, seeded by `RETURNING old.position`.
7. **Track history.**
   - A `history` consumer group writes thinned `track_points` with COPY into daily partitions with BRIN.
   - Est. 10k rows/s and 0.5–1 PostgreSQL core, which breaks the laptop envelope.
8. **Organisations and roles.**
   - Device credentials stamp `org_id`, and positions route on `fleet.pos.<org>.<quadkey>`.
   - Largest blast radius; the brief allows mock identity.

**Build first:** zone entry and exit.
- Best value ÷ cost, and the others depend on it.
- It is the first per-device state beyond the watermark, so it tests the hardest backend part.
- Watch the burst when a zone is created over the whole fleet (est. 300k membership inserts within 5 s).
