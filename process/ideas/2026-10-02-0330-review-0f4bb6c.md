# Review of 0f4bb6c (raw)

Triage in [ideas](../ideas.md).

I found two medium-or-higher bugs in 0f4bb6c, plus two medium problems in the benchmark tools. Note that HEAD has since moved to 3f278e3 (a README-only commit), so I reviewed 0f4bb6c directly. I read code only and ran nothing.

## Medium-or-higher findings

**1. High: cancelling a `Window` waiter leaks permits and stalls a socket's acks** (`ingest.py:62-78`)
- **Scenario:** under load, `asyncio.timeout` in `publish` fires. `Task.cancel()` cancels `grant` at once, but the task's `except` block only runs on a later loop step. In between, a Kafka done callback runs `settled → release(1) → wake()`. `wake` pops the cancelled `grant`, subtracts `count` from `free`, and then `set_result` raises `InvalidStateError`.
- **Effects:**
  - Those permits are lost for good.
  - The other waiters are not woken in that pass.
  - `settled` dies before `acks.settle`, so that socket's ack prefix freezes and its `flush` hangs.
  - The waiter's `except` then calls `waiters.remove`, which raises `ValueError` because the entry is gone. That replaces the cancellation, so the client gets a 500 instead of a 503.
- Repeated, this shrinks the window until ingest stops. The new test does not cover the race.
- **Fix:** `wake` skips futures that are already done, without taking permits; the `except` removes the entry only if it is still in the deque.

**2. Medium: a replay still loses alerts for any device with several samples in the batch** (`processor.py:59-67`)
- The float round trip itself is fine: `orjson`, binary float8 through ST_Y/ST_X, and PG17 numeric `extract` give exact equality.
- **The problem:** only a record equal to the stored row is re-emitted, and the stored row is the device's newest sample.
- **Scenario:** a batch holds a device at t1 (inside a zone) and t2 (outside). The DB commits, then the publish stalls or the process crashes. On replay t1 is neither fresh nor identical, so its inside alert is gone. This is exactly the case CLAUDE.md's rule "every fresh sample is matched before the latest-only reduction" exists for.
- **Side effect:** any client resend or non-idempotent producer retry matching the stored row now re-alerts, which is what `test_an_identical_replay…` actually tests.
- **Fix:** in the batch transaction, store each partition's highest offset (for example a `consumer_progress` table). Records at or below that offset are replays: match and emit them all. Records above it go through the normal watermark check. That removes the tuple-equality rule (rewrite the CLAUDE.md line) and makes client duplicates stale again.

**3. Medium: the benchmark hangs or misreports after faults**
- **`generator.py:205-207, 295-296`:** after the shard-wide reconnect cap, a lane returns but its queue keeps filling. Reports already queued are counted as scheduled (and in the checksum) but never sent or errored. Then `await lane.put(None)` on the full queue blocks forever.
- **`benchmark.py:57-64`:** if `subscribe()` keeps failing, the loop retries forever. `stop` is only checked in the `TimeoutError` branch, so `gather(*watchers)` hangs.
- **`benchmark.py:273-276`:** delivery requires counts exactly equal to `acked`, but the pipeline is at-least-once (replays, plus resends now re-emitted). Any processor or ingest fault fails reconciliation. Deduplicate observed events by fingerprint.

**4. `stored_latest`:** no injection risk. The prefix is internal uuid hex, so no quote, `%` or `_` can appear.

**5. `plan_cache_mode=force_custom_plan` on every pool** (`db.py:20-23`): this re-plans three queries with 2000-element arrays per processor batch, about 1–3 ms each, which is low cost. But it is a global knob that `zone_occupancy` silently depends on. Put `SET plan_cache_mode = force_custom_plan` on the function itself, and use `SET LOCAL` for the snapshot query only.

## Rule violations
- **NULL-or-array branching is still written two ways.** `devices.py` uses one `cells IS NULL OR cell = ANY(cells)` predicate; `zone_occupancy` (`003:39-52`) repeats the whole SELECT in two IF branches. Use the single predicate in both.
- **`models.py:42` still lacks `fillfactor=70`.**
- **Migration 002 was edited in place.** That only affects fresh databases; one that has already applied 002 keeps 100% packing.
- **003's `downgrade` does not restore the 002 version of `grid_cells`.**
- **Untested:** `PublishStalled`, a crash-replay (the test uses a client duplicate), the `owned` seek filter, multi-part (antimeridian) footprints in the grid test, and the Window cancellation race.

## Commit-message claims not delivered
- "A crash … between commit and NATS no longer loses live events": false for devices with several samples in a batch.
- "Granted whole": yes, but permits leak on cancel (finding 1).
- "Folded by custom plans": nothing shows it.
- "Zone occupancy is one SQL function": yes, but it duplicates its query internally.
- "Generator reconnects and resends" and "observers survive closures": both can hang (finding 3).
